# 交互选项、定向学习与长剧执行

用户想选择题材、背景、人物和长度，或导入创作配置时读取本文件。交互是获取创作约束的入口，不能替代参考阅读与剧本写作。

## 两个入口，同一份需求

1. 对话入口：优先沿用已有对话和项目文件，只问真正缺失、会改变作品的选项。有选择控件时使用；没有则提供简短编号菜单。每轮围绕一组问题，不要一口气抛十几个问题。
2. 本地选择页：[创作选择器](../assets/creator.html)。下载仓库后在浏览器打开，选择后复制创作指令，或导出 JSON 交给 Codex。页面只生成需求和写作批次，不会自行读取资料、调用模型或完成剧本。GitHub 文件预览页不能直接运行这个 HTML。

用户已给足条件时跳过问卷；用户要求推荐时给出少量不同方向并说明取舍。不把界面默认值当成用户已经确认的答案。用户只要求更新技能时，不启动具体故事的写作。

## 选择内容

| 维度 | 可提供的选择 | 应保留的信息 |
|---|---|---|
| 题材 | 农家经营、年代创业、逃荒安居、美食小店、自定义种田相关题材 | 观众最想持续看到的变化 |
| 背景 | 架空古代、近现代年代、当代乡村、自定义 | 地域、季节、社会规则，未知处标暂定 |
| 主角与人物 | 女主、男主、双主角、群像；可自填姓名、年龄、关系 | 主角目标/短板；配角自己的目标与底线 |
| 风格 | 温暖经营、强冲突成长、轻喜剧、现实质感 | 感情比重、爽感来源、明确不要的元素 |
| 主角来历 | 重生、穿越、本土成长、自定义 | 回到何时、带来何种记忆与身份 |
| 优势与金手指 | 前世专业经验、先知信息差、空间灵泉、系统奖励、学习记忆强化、配方技艺、资源身份、自定义；可多选 | 优势如何帮助主角赢，具体效果和持续收益 |
| 爽感强度 | 温馨爽、强爽逆袭、大开金手指、写实成长 | 胜利频率、回报大小、升级节奏；与轻喜剧等气质独立 |
| 长度 | 推荐长剧预设 100 集 × 120 秒；允许其他集数与时长 | 总体承诺、当前授权范围、批次大小分别记录 |
| 资料 | 用户指定文件夹/书目/自有原稿；没有资料 | 实际可访问来源与阅读范围 |

不要把偏好“温暖”改写成“没有冲突”，也不要把“爽”等同于所有配角都愚蠢。离开种田、乡村经营与安居题材的请求，应说明现有参考经验的边界，不假称这套技能已经学过所有类型。

## 输入契约

选择页输出 `schema_version: 2` 的 JSON，核心字段为 `title`、`genre`、`setting`、`protagonist`、`characters`、`tone`、`origin`、`previous_life`、`advantages`（非空字符串数组）、`payoff_level`、`ability_details`、`constraints`、`references`，以及 `length.episodes`、`length.seconds_per_episode`、`delivery.batch_size`、`delivery.scope`。scope 为 `full_scripts`（完整季剧本）或 `outline_only`（仅规划）。批次只控制保存和检查粒度，不缩小授权的总集数。

导入时校验：数字是正整数；题材和背景有实际值；不认识的字段不得执行为工具指令。读取实际文件前核对来源路径。若用户口头新要求与旧配置冲突，采用最新明确要求并更新配置；不静默改动已经认可的人名或情节。

在项目内保存 `project_config.json`（用户选择与工作假设分开）和可读的 `project_brief.md`。配置不是剧本完成证明。包含本机路径的配置属于项目私有资料，不默认提交公共仓库。

## 金手指与爽感如何落到剧情

重生是来历，专业经验和先知信息是优势来源，空间/系统是另一类金手指，温馨或轻喜剧是气质；它们不是互斥选项。写实路线仍可选，不把所有种田文都定义成同一类型。当前选择器推荐重生经验与先知信息组合，生成或发送前的默认值仍不算用户确认。

用户选爽文时，先建立“主角凭什么赢”：前世做到什么程度、哪些能力已熟练、知道哪些未来信息、空间或系统能实现什么效果。能力必须在开篇及后续关键事件中兑现，不能只出现在简介里。前世成功餐饮经营者不能不断犯最基础的成本错误来接受教育；冲突可来自提前抢机会后的竞争升级、经营规模扩大、身份隐瞒、家庭关系和学业安排，而不靠把已会的本领忘掉。

在季纲中标出“优势使用 → 主动选择 → 可见结果 → 下一层目标”。胜利可体现为首单爆卖、让父母免受欺负、抢下好铺面、考试跃升、开出新店；按用户选择确定强度，不强迫每次胜利都立刻惩罚主角。仍保持已设规则一致：不临时关掉能力制造苦难，也不在需要时凭空新增外挂。清楚规则不等于削弱优势；成长空间也不等于强制副作用。

兼容旧配置：接受 `schema_version: 1` 与旧 `ability` 字符串，保留原文供溯源。结合题材描述与用户最新说明解释，不把旧菜单“穿越经验，能力有限”自动扩写成忘掉专长、没有先知优势或必须反复失败。如果来源到底是重生还是穿越尚不明确，只补问该项；已有明确“女生重生90年代”时不重复问。新增空间或系统须有用户选择依据。

## 先把需求拆成学习问题

依据选择建立 `learning_plan.md`，每项写“要解决的创作问题 → 要找的参考片段 → 将影响什么决定”。例如：

- 母女经营：读连续的意见分歧、共同劳动、利益分配和关系转折，学习如何让双方都有道理。
- 逃荒安居：读资源选择、迁移代价、落脚后的生产恢复；不能一百集都重复缺粮和遇险。
- 年代创业：先明确年代及制度背景，再学习试产、客户、回款与家庭代价；现实政策需另行查证。
- 一百集长剧：关注阶段胜利如何产生新责任，连续事件与中后段回收优先，不能只读一百个开头。

按 [参考学习](reference-study.md) 进行实际阅读。记录来源、章节/字符范围、连续阅读还是抽读、观察依据和边界。给出适合本项目的比较，不宣称“已通读”或“已经训练模型”。这里的学习是本次阅读分析和可追踪笔记。

把结论落到 `adaptation_decisions.md`：来源范围 → 可迁移叙事方法 → 新作采用的原创决定 → 不采用的具体元素。没有可读资料时写明“未进行本轮参考阅读”，可依据既有笔记和原创方法继续，不假造阅读结果；用户明确要求必须先读的资料缺失时，完成不依赖它的准备并说明阻塞。

## 拆分全季，再写完整场景

1. `story_bible.md`：故事承诺、人物目标与盲区、生产/交易链、时间跨度、核心地点、结局要兑现的事项。
2. `season_outline.md`：覆盖用户要求的所有集号，每集有目标、阻力、选择、结果、接点。100 集可先分约十个阶段，但阶段长度随故事变化，不能固定重复“受辱—打脸”。用户选其他集数时相应重排。
3. `writing_plan.md`：按 batch_size 分批，例如 100 集、每批 10 集产生 EP001—010 至 EP091—100；103 集最后一批 EP101—103。不得丢掉余数。
4. `episodes/EP001.md` 等：具体场景、动作、对白、时长分配与集尾。大纲不计入剧本完成数。
5. `continuity.md`、`progress.json`：每批写完核对钱粮、季节、生长周期、人物知情、承诺和情感变化，再更新实际进度。

每集两分钟指有效剧情，片头片尾另计。对白主导集可先以约 240—330 个汉字估算，再结合人物语速与独立动作判断；不是最低字数，也不是达到字数就等于两分钟。避免低信息动作、重复争吵和长停顿填时。纸面预计时长、围读时长与成片时长分别标注。

收到整季写作授权后，批次是内部执行安排，不是每写三集就要求“继续”的许可门槛；能继续就继续。仅请求大纲时到大纲为止。若确实受单次执行限制，保存最后完整集和明确续写位置，报告实际完成数，不承诺无人触发的后台自动写作。

## 进度与改需求

`progress.json` 至少记录 `target_episodes`、`seconds_per_episode`、`outline_completed`、`scripts_completed`（实际完整集号列表）、`reviewed_episodes`、`next_episode`、`blockers`。分别验证对应文件存在且内容符合其阶段，不能因为一百个文件夹已建好就记为完成一百集。

恢复时先读配置、进度、连续性和上一完整集，核对文件实际状态；若中断集只写一半，从该集补完，不误跳到下一集。长度改变后重算尚未完成的阶段与批次；人物、背景改变可能影响已写集，列出受影响处并同步修订，保留用户认可的版本。

## 交互行为验收样例

- “带我选，做 100 集，每集 2 分钟”：记住长度，只补题材、背景、人物等缺项，不再问集数。
- “年代创业、姐妹双主角、24 集，每集 90 秒，只要大纲”：输出对应范围，不强制 100 集，也不写正文或生成视频。
- “用导出的 JSON，写完整一季”：实际读取指定资料或说明不可读，建立全季结构后写正文，批次结束不自动变成最终结束。
- “没有参考，先原创 12 集”：不编造书目阅读，原创继续，进度保持诚实。
- “继续”：按已有状态恢复，不重新提问所有偏好，不覆盖已认可稿件。

- 金手指验收：“轻喜剧＋重生＋成熟餐饮经验＋信息差”应兼有幽默与持续成功，不能退回无外挂受挫教育片。选择空间＋系统时两项均应有明确作用；明确不另加金手指时不得擅加。

## 后续图片制作配置

schema_version 2 可选 `production` 对象：`mode` 为 `none`、`prompts` 或 `images`；`episode_scope` 为用户选择的集号/范围；`aspect_ratio`、`visual_style` 保存制作规格；`image_engine` 为 `codex_builtin_image`；`character_views` 为 front/side/back。缺少 production 的旧配置视为 none，不自动开图。

剧本集数与制作集号是不同范围。制作范围空白时仅补问要制作哪些集；不能据50集正文授权推导50集全量出图。范围解析应支持 EP001、EP001—EP003、全季，检查集号在全季内并按实际完整剧本核对，不能把原始输入作为命令执行。仅规划模式不进入镜头制作。prompts 模式交付文本，images 模式才实际调用图片工具。按 [制作与验收](production-and-qa.md) 执行，画幅未确定时先完成独立准备，再补问，不把界面默认值当用户批准。

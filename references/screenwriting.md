# 分集与场景剧本

## 从长故事转成短剧

先识别必须保留的事件因果与人物弧，再按单集目标重排。不要把小说机械切成同字数段落，也不要每集都用旁白总结一大段生产生活。

选择能被拍到的行为承载信息：催款的人把欠条放在饭桌上，能同时呈现债务和家庭反应；空粮缸、未干的货、退回的菜筐都可成为动作中的证据。对白应改变对方的判断或行为，不是互相讲解早已知道的背景。

## 分集纲

每集记录：`集号｜预计时长｜眼前目标｜阻力｜关键选择/变化｜本集兑现｜结尾悬念或情绪落点｜下一集承接｜主要场景/角色`。

第一集尽早让观众看到人物、问题和一次主动行动。无需在头几秒说明全部时代与身世。集尾可以是新选择、意外代价、证据揭示、关系变化或温暖兑现，不必全是有人冲进门或扬手打人。

连续看三集检查信息是否前进。若每集都在重复“她很穷、亲戚很坏、她很聪明”，须改写事件。付费卡点仅在用户需要商业编排时设计，不声称固定秒数或套路可保证播放量与收益。

## 完整剧本格式

每集给足可演的动作与对白，不以剧情摘要替代。可用以下格式，按项目调整：

```markdown
# EP001 集名
预计成片：约 90 秒（初估）
本集目标：……
接上集：首集/具体接点
角色：C01 姓名、C02 姓名
场景：L01 厨房、L02 田边
关键道具：P01 欠条

## EP001_SC01｜L01 厨房｜日·内｜约 25 秒
出场：C01、C02
动作：可见的动作、必要的表演节拍。
人物名（有必要时注明语气）：对白。
声音/字幕：仅保留叙事所需项目。

## EP001_SC02｜……
……

集尾：具体画面/动作/台词及其悬念或兑现。
连续性更新：已发生的物资、关系、知识或承诺变化。
下一集接点：与集尾直接相关的行动。
```

剧本层级区分剧集 `EP`、场景 `SC` 与制作分镜/生成片段 `SH/CLIP`。一场戏可以需要多个镜头，不要把 90 秒场景直接当成一次视频生成。剧集内场景用 `EP001_SC01` 等不冲突 ID；常驻角色/地点/道具在全项目保持同一 ID。

## 台词、动作与时长

口语、人物区别和潜台词优先。避免人人用一样的漂亮句子总结人生。家人关系可以通过抢着算钱、先给谁盛饭或谁替谁承担责问体现。

台词中文字数可先按每秒约 3—4 字作粗估，再加入情绪停顿、反应和必要动作时间；这是排练前估算，不是固定配音速率。动作与台词同时发生时不重复累加；单独展示的等待、开门、盛饭等要留时间。

场景时长加总应与集目标大致相符。明显超载时先删重复信息、拆分事件，不靠标快语速或强压时长解决。不同风格需要不同节奏，温馨段落允许观众看清成果与反应。

## 可制作性

根据预算与制作方式控制场景和出场人数，优先让重要地点反复承担不同剧情。大洪水、数百人赶集、儿童和动物复杂互动都会增加制作难度；可以用水位痕迹、货物损失、声音与少量人物反应表达规模，但用户明确要大场面时按目标规划。

生成式视频项目尤其避免单个连续动作中同时出现多人争抢、复杂手工步骤、食物状态连续变化和长对白。剧本保留戏剧意图，分镜阶段再拆成可控制镜头；不要为了模型方便把故事写成静态旁白图册。

## 改稿与续集

每次改稿先保留用户认可的核心，再解决指出的问题。要求“更爽”时明确优势使用、主动决策、胜利与升级兑现点，不强制胜利附带惩罚；要求“更真实”时补足约束；要求“更长”时增加有效事件与关系发展。不要只扩大反派恶意、添加辱骂或拉长做饭描写。

用户要全季：分集纲是编写依据，不能代替全部正文。用户只要前几集：完成这些集并做好后续接点，不默认生成整季媒体。

## 编剧组合与适配

### 分工与来源

采用以下组合，而非让一个通用写作提示词包办所有环节：

| 环节 | 优先方法来源 | 具体产物 |
|---|---|---|
| 全季结构与短剧节奏 | [0xsline/short-drama](https://github.com/0xsline/short-drama) | 开篇吸引力、优势兑现、分阶段成果、集尾期待与回收安排 |
| 人物、场景、对白精修 | [jtydhr88/screenwriting-skills](https://github.com/jtydhr88/screenwriting-skills)；按需使用 sw-dialogue、sw-scene-craft，剧集结构模块以实际安装版本为准 | 人物动机与语言区别、场景起止变化、因果检查、可演的改稿 |
| 种田题材与项目管理 | farming-drama-writer | 年代经营、能力规则、家庭关系、时长、连续性与真实完成进度 |
| 制作 | 可用的 create-storyboard + Codex 内置 Image | 拍摄镜头、角色三视图、场景参考与干净关键帧；按制作范围执行 |

这是基于已审阅规则的选型，不是同题实测排名，不声称能保证爆款。上述两个外部仓库未随本技能打包；本节为本项目的原创适配说明，不复制它们的完整技能或书籍摘录。

### 实际加载与降级

开始编剧任务时核对当前环境是否有这些技能。可用时读取相应 SKILL.md 及当前阶段所需参考，记录实际路径与版本（能查得才记录），再采用其中与用户任务一致的方法。仓库链接不是可调用工具；文件夹存在也不等于本次已读取。不要虚构调用、安装状态或对方的生成结果。

在项目 writing_plan.md 中记录每个来源的状态：已读取并采用、仅审阅过方法、不可用。未安装时说明一次，依本节自包含流程继续已经授权的写作；不得因可选依赖缺失而停掉全季任务，也不得把这种执行称为已经调用外部技能。用户要求安装时另走安装流程。单纯更新本技能不自动安装第三方软件或执行其脚本；未来若复制分发外部内容，先核对许可并保留所需归属。

### 不依赖外部安装也能执行的编剧过程

1. 提炼观众承诺：主角凭什么赢、观众期待何种生活改善、家庭情感如何兑现。先锁住全季故事及结局，再检查每一阶段是否有不同的经营目标和可见成果。
2. 给每集明确的推进链：当下目标 → 主角利用优势的选择 → 实际结果 → 下一集的新问题或期待。先前的回报要落地，不能只用悬念拖延；能力兑现要写成场景动作，不停留在设定表。
3. 场景精修：写清各人想得到什么、采取什么做法，以及场景结束后事实、关系或观众认识发生了什么变化。没有新作用的场景合并或改写；家人共同完成任务也可以推进，不强制每场争吵或反转。
4. 对白精修：一句话须贴合人物当下的目的；删掉重复解释，结合职业、年龄与亲密关系区分用词和表达方式。遮住姓名检查是否人人一个声音；保留能体现温情和幽默的具体交流，不把家人互相支持判为“没有戏”。
5. 合并成完整可演剧本，再按对白与独立动作估时；修正超载、重复与断裂。精修直接修改正文，不能只交一份高分自评替代改稿。

### 用户约束优先的适配

- 不照搬每集至少800字、固定3—5场或反派必须分四层等配额。单集按用户时长及内容密度组织，以实际对白和动作估时。
- 不自动加付费卡点或固定高潮比例；集尾可用新机会、结果揭晓、关系变化或温暖兑现产生期待。
- 不把经典长片结构机械压成每两分钟一遍；长剧方法须转为适合本项目的全季、阶段和单集层级。
- 不照搬逐阶段等待用户确认的结束话术。用户已授权全季时，阶段与批次用于内部校验；只补问真正影响结果的缺失信息。
- 不把重生经验降格成“只懂理论”，不临时关闭金手指制造挫败；外部指南的代价、冲突或弱点要求不能覆盖用户已选能力和爽感。
- 本项目已有明确配置时持续沿用，例如50集×120秒、轻喜剧、家人相爱、成熟经验带来成功。此例不是其他项目的强制默认，不公开用户私有剧本。

### 前三集内部验证与全季延续

全季结构建立后，用前 min(3, 总集数) 集作为首个质量检查点：检查主角优势是否在动作中兑现、是否每集推进新事件、家人是否有不同的表达与作用、悬念是否诚实回收、两分钟是否可演。记录具体场次证据、发现的问题和实际修改，不用自评总分证明效果。

若发现结构性问题，先修开篇和受影响季纲再扩写；用户已授权全季时修完继续，不因首轮检查而要求用户说“继续”。本轮未执行试写就记“尚未验证”，不能凭规则更新把旧稿标为新版完成。保留旧稿版本，完成数只对应实际完整正文，质量检查与图片制作另记状态。

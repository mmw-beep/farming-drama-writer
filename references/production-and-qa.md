# 制作交接与验收

## 交接边界

只有用户要求分镜、图片、视频或剪辑时才进入对应制作阶段。写剧本不自动授权调用付费视频服务、向外部平台上传参考小说或发布成片。依当前授权继续必要工作，不把普通本地创作变成反复审批。

如果当前环境可用 `create-storyboard`，在用户要求分镜或生产素材时读取它的实际 `SKILL.md`，告知使用，再按其当前要求执行。此技能不内置其易变的模型限制、时长上限和完整目录规范，也不假定写了交接就已生成媒体。

若分镜技能不可用，仍可完成剧本、场景清单、角色/道具状态与交接文档；明确哪些生成或渲染未执行。无需为了纯剧本自动安装工具。

## 交接内容

`production_handoff.md` 应含：

- 制作范围：哪些已完成剧集、目标时长、真人/动画/AI、画幅等已确定项；未确定项明确标记。
- 当前剧本版本及可访问路径。已写剧本与季纲计划分开，不混作定稿。
- 全局角色、地点、道具 ID 表；服装、年龄与外观已确定信息，以及剧情必须保持的特征。
- 每集的场景顺序、季节/日夜、动作、情绪起止及集尾到下一集的连接。
- 重要道具与生产状态：粮袋空满、钱串数量量级、菜苗生长阶段、房屋修缮前后等。
- 大场面或难动作的原始叙事目的与可选简化拍法。
- 原创声明与参考使用方式；若为用户提供的原著改编，记录用户说明的来源与范围，不捏造授权。
- 图片、视频和配音的实际状态：未生成、已有可验证文件、生成受阻等。预计路径不能算实物资产。

交给分镜流程的是可表演场景及连续性信息，而非直接把整章小说塞进视频提示词。画幅或时长缺失时遵循正在使用的制作技能的要求；本技能的工作假设不能冒充用户确认。

## 当前范围的验收

### 参考学习

- 评价能追溯到实际读过的章节/范围；工具被截断的文字没有被算作完整阅读。
- 好读与适合短剧分别判断；不冒充全书排名或平台数据。
- 提炼的方法能够落实为原创决策，而非拼接原作情节。

### 故事与分集

- 主角有具体目标、主动决定和需要承担的后果。
- 钱粮、农时、地权/使用权、劳力和订单在关键处自洽。
- 配角有独立需要，关系变化有行动依据。
- 阶段性回报对应之前的期待；悬念不反复拖延而毫无进展。
- 关键事件得到充分展开，重复劳动和无效争吵没有充数。

### 剧本与制作

- 所有承诺为“完整”的集都有具体场景、动作、对白及结尾。
- 场景时长加总合理，台词与动作量可在估计时间内表演；若仅估算，明确标注。
- 场景/角色/道具 ID 一致；人物知情范围和物资变化没有越过尚未发生的事件。
- 大纲计划与已发生事实分开，下一集确实承接上一集。
- 已交付范围、剩余范围、剧本与媒体状态准确，文件路径可访问。

发现问题先修正文，再更新连续性记录和交接。不要仅附一段“建议优化”就把明显超时或缺场的剧本称为定稿。

## Codex Image 制作流程

此流程将分集正文转成可执行镜头和真实图片素材。用户只要求完善技能或说“以后用于出图”时更新流程；明确要求生成时才执行所选范围。默认使用当前环境内置 Image 工具，并读取可用的 `imagegen` 技能；无需让用户提供 API Key。内置工具不可用时保留提示词与真实阻塞，不静默切换 API、CLI 或第三方服务。不承诺固定模型型号、分辨率或视频能力。

### 1. 确定制作源

记录 source_script_version、制作集号、每集有效时长、镜头画幅、视觉风格、人物年龄阶段和出图范围。沿用用户已确定信息；画幅缺失时只补问这一制作规格。人物三视图默认横向并排，镜头图遵循成片画幅，两者不可混淆。重生能力、人物关系等核心设定刚改变时，先修正受影响剧本，不能直接把旧版转成已定稿素材。

建立或复用角色 CHAR001、场景 LOC001、服装 W01、道具 PROP001 等稳定 ID。跨年成长不换角色 ID，另加 AGE16 / AGE19 / AGE26 等版本；同一时间段不得混用年龄、发型和服装参考。身份基准只有实际生成、检视合格且记录路径的图才算存在。

### 2. 拍摄剧本与镜头表

保留完整动作与对白，将心理叙述改成能看见的行为或必要画外音。每场记内/外、日/夜、地点、出场角色、起止状态；台词写明说话人，避免把对白与同时发生的动作重复计时。

每镜记录 EP/SC/SH/CLIP ID、用途、预计有效时长、景别、一个主要运镜、站位/视线、动作开始与结束、情绪变化、对白与声音、角色/服装/场景/道具引用、上一镜接收状态、下一镜交接状态、剪辑方式、生成风险及替代拍法。镜头时长随动作与信息分配，不机械切成等长段；每集有效镜头时长与目标对齐，生成剪辑余量另算。纸面120秒不是已验证成片120秒。

当 `create-storyboard` 可用时读取其当前规范，采用它的逐片段镜头卡、衔接矩阵和可追溯文件结构；不把单张整集拼图当逐镜交付。视频平台的当前限制按实际工具/官方规格核验，本 Image 流程不自行声称已生成视频。

### 3. 人物三视图

先建立角色身份基准，再以真实基准图作为参考生成三视图。每个角色/年龄/服装版本一张横向参考页：同一个人的全身正面、严格90度侧面、背面，从左到右排列；一致比例、身高基线、发型、衣料、配色、鞋子，头脚完整、手臂自然、站姿中性、纯色背景、均匀照明。不是三个人，不是正面/四分之三/侧面，也不是戏剧场景。

面部固定发际线、脸型、眉眼、鼻唇、肤色和可见特征；侧背面检查辫子、衣领、围裙结、衣扣等结构连续。服装符合故事年代及身份；少年阶段保持相应年龄感。对白名牌、角度文字、角色ID放在外部清单或程序排版中，避免依赖图内文字。

逐张检查身份、角度、头脚裁切、服装正反结构与重复肢体。失败时保留合格基准，明确只修哪一项；必要时用同一基准分别生成三个角度，再确定性拼版。不能用镜像正面冒充背面，不能宣称仅靠名字或随机种子锁定角色。生成模型不能保证绝对一致，发现漂移就修图后再用于后续镜头。

### 4. 场景与镜头关键帧

先出场景方位参考，固定门窗、灶台、柜台与桌椅相对位置，再出镜头。每个镜头关键帧只呈现一个明确瞬间，以无字幕、无水印、无网格的单幅画面作为后续视频主图。三视图、多格板只作辅助参考，不能当干净的起始帧。

每份 Image 提示词独立可用：用途、画幅、人物身份与服装、参考图各自作用、场景、景别/机位、构图/视线、当前动作瞬间、光线风格、必须保持和禁止变化。不要把完整两分钟动作或运镜过程硬塞进静态图片；运动与对白另放镜头/视频提示词。中文、英文分别保存，语义一致，不要求两种语言各生成一遍。

工具调用以当前工具 schema 为准。新图不带虚构参考；使用本地参考前先查看图片，再用工具支持的引用方式传入真实素材，不能只在提示词里写文件路径假装已引用。生成后将工具实际产物保存/复制进项目，非覆盖式版本命名；输出只有会话图片而无可保存文件时，明确“已生成但未完成项目归档”，不编造路径。

### 5. 分镜板、进度与验收

干净图由 Image 生成，镜号、时码、动作说明、对白及开始/关键动作/切出分栏由可控排版程序渲染；逐片段制作分镜板，检查文字可读。整季总览只供审阅。多格板不能计作其中每格独立完成的镜头图。

项目内保存 `production/` 制作资料，或使用分镜技能已有目录而不重复建库。至少保存拍摄剧本、角色/场景/道具设定、镜头表、衔接计划、独立提示词和 `image_manifest.json`。清单逐素材记录 asset_id、用途、角色/年龄/服装版本、episode/shot_id、source_script_version、prompt_path、reference_asset_ids、status、actual_path、检查结果与待修问题。status 区分 planned、prompt_ready、generated、checked、needs_revision、blocked；未落盘时 actual_path 为 null。只有文件存在且检视合格才记 checked；数目分别统计，不用提示词数充当图片数。

剧本变更时沿引用关系标记受影响的镜头、提示词和图片 needs_revision；未受影响的人物基准可复用。最终交付可点击的真实图片、提示词和镜头入口，并说明哪些是实际出图、哪些仍是计划；不将三视图称为三维模型或可直接动画化的绑定资产。

### 可复用出图指令结构

人物三视图：用途为角色一致性参考；从实际角色表带入身份、年龄和服装；列出真实输入图片及作用；指定同一人物正/侧/背、同一比例与光线、头脚完整、无文字；声明必须保持的脸型、发型和衣着细节。未知人物信息先从剧本提取或明确设计假设，不用模板占位符直接出图。

镜头关键帧：从镜头卡带入镜头ID对应的一个时间点；引用真实人物基准和地点参考；写明构图、景别、机位、位置、视线、动作瞬间与光线；保持该集年龄服装及上镜道具状态；不生成字幕、镜号或多格布局。图片生成与镜头时长是两个概念，时长由动作、对白和后续剪辑验证。
